# Visual evidence and provenance

These assets are generated by [`generate_assets.py`](../generate_assets.py) with
NumPy, Matplotlib and Pillow. They contain simulation results and recorded
experiment data, rather than generated illustrations.

```bash
# Re-render all figures and animations using the committed rollout cache.
python generate_assets.py

# Re-run the 21 deterministic policy episodes, then render every asset.
python generate_assets.py --refresh-rollouts
```

The refresh command loads the committed Stable-Baselines3 checkpoints on CPU.
It performs evaluation only; it does not train or alter models. No display or
Pygame window is needed. Minor numerical differences may occur with different
Python, NumPy, Torch or Stable-Baselines3 versions. The default command uses the
frozen numerical cache so the original visual evidence remains inspectable.

| File | What it shows | Source |
| --- | --- | --- |
| `training_demo.gif` | Two separate scenes: actual PPO checkpoint driving on a fixed ellipse; then the recorded best fitness across 20 evolutionary generations | Fresh PPO evaluation plus `evolution_shared_physics/training_history.csv` |
| `racing_trajectories.png` | Actual Broad Domain PPO, tuned Pure Pursuit and evolved geometric paths on one circuit in each of five families; failures are marked × | Fresh benchmark trial `10000`, start index `0`, reset seed `12345`, shared `RacingEnv` |
| `driving_maps.gif` | The same 15 driving episodes animated against one common simulation clock | Same cached trajectories as the static comparison |
| `performance_comparison.png` | Completion across all 20 cases per family; mean lap time on cases completed by **all three** controllers | Raw CSVs in `baseline_comparison_tuned/` and `evolution_shared_physics/` |
| `evolution_learning_curve.png` | Final view of the 20-generation logged evolutionary search | `evolution_shared_physics/training_history.csv` |
| `rollouts.npz` | Frozen coordinates, simulation times, speed, progress, heading and track geometry | 21 complete deterministic evaluation episodes |
| `rollouts.json` | Episode outcomes, actual checkpoint timestep counts, array column names and replay input hashes | Metadata captured when the rollout cache was generated |
| `manifest.json` | Hashes for visual inputs and the rendering script; matched sample counts | Automatically written by the generator |

## Interpretation

- **PPO timesteps and evolutionary generations are separate training units.**
  The GIF uses distinct scenes and does not imply equal compute or equal budgets.
- PPO filenames mark requested milestones. The displayed counts come from model
  metadata: `0`, `26,624`, `53,248`, `104,448`, `256,000`, `507,904` timesteps.
  Each ellipse rollout uses `ppo_learning_replay.track_points("ellipse", 0)` and
  reset seed `20261115`. Episode playback lengths are normalized; the displayed
  simulation time is accurate. The early checkpoint's timeout is retained.
- The evolutionary learning curve is the **shared-physics geometric controller**
  training log on trials `200–201` in each family. Only its final controller was
  saved, so there are no reconstructed or invented intermediate driving paths.
  The separate `racing_showcase.py` population demo uses different vehicle physics
  and supplies none of these benchmark statistics or trajectories.
- The map GIF uses a shared simulation clock, accelerates playback, and freezes
  each vehicle when its episode ends. The figure deliberately includes failures:
  trial `10000` has evolved-controller failures on ellipse and wavy, and a PPO
  failure on hard spline. These are illustrations, not a representative average.
- The statistics join cases by `(family, trial)` and check duplicated PPO records
  agree across source CSVs. The three-way successful intersection is
  **7 / 12 / 18 / 14 / 6** cases for ellipse / wavy / complex / spline / hard spline.
  These lap-time means exclude failures and must be read with completion rates.
  They differ from means over each policy's individually successful runs.
- All three benchmark policies share physics, track and starting pose. Geometric
  controllers have full-centerline access, while PPO has local observations;
  information access and training budgets are not matched. Results do not prove
  a universally superior controller or optimal racing line.
